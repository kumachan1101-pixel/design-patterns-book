# 『デザインパターン C++ソフトウェア設計』掲載コード（改訂2）

**改訂後の本文に対応するフォルダです。** 本の「おわりに」の「掲載コードについて」に `volume01-rev2` と書かれている方は、このフォルダを使ってください。`volume01-rev2` と書かれていない版（最初に公開した本文）をお持ちの方は、[`volume01/`](../volume01/) を使ってください。

各章のコードを、本文で追う順に並べています。

**Windows では、このフォルダの [`run.bat`](run.bat) をダブルクリックしてください。** 章とコードの種類を番号で選ぶと、ビルドして実行します。C++ コンパイラが必要です。準備の手順と注意点は、リポジトリ直下の README の「[Windows での注意点](../README.md#windows-での注意点)」にまとめています。macOS・Linux では各フォルダで `make run` を使います。

| フォルダ | 章 | 扱うパターン |
|---|---|---|
| [`ch01-strategy/`](ch01-strategy/) | 第1章 | Strategy（割引ルールの差し替え） |
| [`ch02-state/`](ch02-state/) | 第2章 | State（予約状態の遷移） |
| [`ch03-observer/`](ch03-observer/) | 第3章 | Observer（在庫警告の同報） |

## 各章のフォルダ構成

| フォルダ | 本での位置 | 中身 |
|---|---|---|
| `1-before/` | フェーズ1「現状把握」1-4 | 変更が届く前の現状コード |
| `2-trial/` | フェーズ3「問題特定」3-1 | 変更依頼を **現状の構造のまま** 当てた仮実装 |
| `3-after/` | 「完成形」の「完成コード」 | 構造を変えたあとの完成コード（1ファイル） |
| `4-after-split/` | 「完成形」の「実務でファイルを分けるなら」 | 完成コードを実務のファイル構成へ分けたもの |

**`2-trial` は捨てるためのコードです。** 本文でも「この仮実装は対策案ではない」と書いています。構造を変えずに変更を当てると、依頼にない場所まで修正と確認が広がる——その事実だけを観測するために置いています。

diff を2回とると、本文が追う流れをそのまま確認できます。

```sh
# 変更を当てると、どこまで手が入ったか（＝痛み）
diff -u ch01-strategy/1-before/main.cpp ch01-strategy/2-trial/main.cpp

# 構造を変えたあと、同じ変更がどこへ閉じたか
diff -u ch01-strategy/1-before/main.cpp ch01-strategy/3-after/main.cpp
```

## 先に本文を読むことをすすめます

`3-after` は答えです。本は **変更前のコードへ変更依頼を当て、痛みを観測し、原因から課題を決めてから構造を選ぶ** という順で進みます。先に答えを見ると、その過程が飛んでしまいます。

まず `1-before` を動かし、本文のフェーズ1からフェーズ6までを読み、そのうえで `3-after` を開くのがおすすめです。
